# Лабораторная работа 2: эффективное распараллеливание циклов

Эталонный цикл и индивидуальные варианты **1б** (MPI), **2б** и **3б**
(OpenMP): анализ зависимостей, последовательная и параллельная версии,
проверка совпадения результатов, время, ускорение и эффективность.
Эталонный цикл распараллелен и на OpenMP, и на MPI.

## Методика

- Машина: Apple M3 Pro, 5 производительных и 6 энергоэффективных ядер;
  Homebrew clang 20.1.8 (`-O3 -march=native`), libomp, Open MPI 5.0.7.
- Размеры 1000 x 1000 и 5000 x 5000. Массив в 200 МБ не помещается на стек,
  поэтому сетка лежит в куче, а размеры задаются параметрами.
- Замеряется только гнездо циклов, без инициализации и вывода в файл.
  Время - минимум по 30 (1000) или 7 (5000) повторам. Для MPI время включает
  сбор результата на ранге 0; время одного счёта дано отдельно.
- S = T_посл / T_p, где T_посл - отдельная последовательная программа;
  E = S / p.
- Графики (`plots.ipynb`): точка - минимум, планка погрешности - до
  среднего по повторам, кривая - сглаживающий сплайн времени в координатах
  (log p, log T), из которого получены и кривые S и E.
- Корректность: все версии используют одни и те же тела циклов
  (`include/loops.h`), поэтому результаты совпадают побитово. ctest сравнивает
  их в процессе (`-c`) и через файлы `"%f "`, как требует методичка. При
  5000 x 5000 и 11 исполнителях файлы всех версий тоже идентичны.

## Анализ зависимостей

D = Lambda - K (итерация-приёмник минус итерация-источник), d - вектор
направлений.

| Цикл | Запись | Чтение | D | d | Зависимость |
|---|---|---|---|---|---|
| эталон | `a[i][j]` | `a[i][j]` | (0, 0) | (=, =) | нет |
| 1б | `a[i][j]` | `a[i-2][j+3]` | (2, -3) | (<, >) | истинная, по `i` |
| 2б | `a[i][j]` | `a[i+1][j-6]` | (-1, 6) | (>, <) | антизависимость, по `i` |
| 3б, гнездо 1 | `a[i][j]` | `a[i][j]` | (0, 0) | (=, =) | нет |
| 3б, гнездо 2 | `b[i][j]` | `a[i+1][j-3]` | - | - | внутри нет; истинная от гнезда 1 |

## Эталонный цикл

```c
a[i][j] = sin(2 * a[i][j]);
```

Итерации независимы. OpenMP: `parallel for` по `i` с `schedule(dynamic, 8)`:
при статическом делении всё ждёт медленные ядра, динамическое подняло S при
11 потоках с 5.2 до 6.4. MPI: блоки строк и `MPI_Gatherv` на ранг 0.

## Вариант 1б (MPI)

```c
for (i = 2; i < ISIZE; i++)
  for (j = 0; j < JSIZE - 3; j++)
    a[i][j] = sin(5 * a[i-2][j+3]);
```

Истинная зависимость с D = (2, -3) по внешнему циклу. Цепочка
(i, j) <- (i-2, j+3) <- ... сохраняет k = j + 3 * floor(i / 2), поэтому
разные k независимы. Диапазон k делится между рангами поровну по числу
элементов; в каждой строке ранг считает свой непрерывный отрезок
(полоса-параллелограмм) без обменов, а в конце отправляет полосу на ранг 0
одним сообщением с типом `MPI_Type_indexed`. Каждый ранг трогает только свою
полосу, поэтому память не растёт с числом процессов.

| 2 | 38.51 | 1.72 | 0.86 | 34.83 | 1.90 | 0.95 |
| 4 | 25.81 | 2.57 | 0.64 | 17.94 | 3.69 | 0.92 |

привязать к ядрам, и время определяет самый медленный ранг.

## Вариант 2б (OpenMP)

```c
for (i = 0; i < ISIZE - 1; i++)
  for (j = 6; j < JSIZE; j++)
    a[i][j] = sin(0.2 * a[i+1][j-6]);
```

Антизависимость с D = (-1, 6): каждое чтение должно видеть исходное
значение. По методичке такой цикл можно распараллелить, если продублировать
входные данные.

Схема `2b`: строки режутся на 8 * p блоков (`schedule(dynamic, 1)`), внутри
блока строки идут по порядку. Блок читает чужой только первую строку
следующего блока, поэтому до начала счёта эти строки копируются (барьер
после первого `omp for`). Цена - одна строка на блок.

Альтернатива `2b-cols`: `i` последовательно, `omp for` по `j` в каждой
строке. Копий нет, но 5000 барьеров на 14 мкс работы каждый, и это медленнее
последовательной версии при любом p > 1.

## Вариант 3б (OpenMP)

```c
for (i = 0; i < ISIZE; i++)
  for (j = 0; j < JSIZE; j++)
    a[i][j] = sin(0.01 * a[i][j]);
for (i = 0; i < ISIZE - 1; i++)
  for (j = 3; j < JSIZE; j++)
    b[i][j] = a[i+1][j-3] * 2;
```

Внутри гнёзд зависимостей нет; второе гнездо читает `a`, посчитанное первым.
Слияние гнёзд дало бы d = (>, <), то есть чтение раньше записи, поэтому оно
недопустимо. Схема: одна параллельная область с двумя `omp for`, между ними
неявный барьер. Первый цикл - `schedule(dynamic, 8)`, второй (копирование) -
`schedule(static)`.

## Итоги

| Цикл | Технология | Лучшее S (5000) | E при нём | E при p = 4 |
|---|---|---|---|---|
| эталон | OpenMP | 6.37 (p = 11) | 0.58 | 0.96 |
| эталон | MPI | 3.38 (p = 8) | 0.42 | 0.80 |
| 1б | MPI | 2.77 (p = 6) | 0.46 | 0.64 |
| 2б | OpenMP | 6.21 (p = 11) | 0.56 | 0.94 |
| 3б | OpenMP | 5.23 (p = 11) | 0.48 | 0.88 |

- До 4 потоков (все на производительных ядрах) OpenMP близок к линейному
  ускорению. По закону Амдала из S = 3.83 при p = 4 доля последовательной
  части alpha = 0.015.
- После 5 потоков добавляются медленные ядра: S = 6.37 при 11 потоках
  соответствует примерно 7 быстрым ядрам (5 + 6 / 3), то есть упор в железо,
  а E падает, потому что p считает медленное ядро как полное.
- MPI ограничен сбором результата на ранге 0 (alpha около 0.1) и статическим
  делением, поэтому максимум при 4-8 процессах.
- При 1000 x 1000 цикл идёт меньше 3 мс, и накладные расходы (потоки,
  барьеры, сообщения) заметнее.

## Контрольные вопросы

1. **Ускорение и эффективность.** S = T_1 / T_p (лучший последовательный
   алгоритм к параллельному), E = S / p.
2. **Закон Амдала.** При доле последовательной работы alpha
   S = 1 / (alpha + (1 - alpha) / p) <= 1 / alpha.
3. **Свойства канала.** Латентность и пропускная способность: передача n
   байт стоит примерно латентность + n / пропускная способность, поэтому
   выгодны крупные сообщения и совмещение обменов со счётом.
4. **Режимы MPI.** Синхронный (`MPI_Ssend`) ждёт начала приёма;
   неблокирующий (`MPI_Isend`/`MPI_Irecv`) возвращается сразу и завершается
   через `MPI_Wait`; буферизованный (`MPI_Bsend`) копирует сообщение в буфер
   пользователя. `MPI_Send` может буферизовать малые сообщения и блокироваться
   на больших.
5. **Циклы в OpenMP.** `#pragma omp parallel for` перед циклом канонического
   вида с `schedule`, `private`, `reduction`, `collapse`; независимость
   итераций обеспечивает программист.
6. **Синхронизация** - упорядочивание исполнителей так, чтобы зависимые
   операции шли в нужном порядке: барьеры, критические секции, замки,
   атомарные операции, сообщения.
7. **Условия Бернстайна.** S1 и S2 параллельны, если пусты W(S1) и W(S2),
   W(S1) и R(S2), R(S1) и W(S2) в пересечении. Нарушаются для
   `x = a + b; y = x * 2`.
8. **Расстояние в простом цикле:** D = lambda - kappa. D > 0 - не более D
   исполнителей; D < 0 - любое деление при копии данных; D = 0 - нет
   зависимости между итерациями.
9. **Для вложенных циклов** D - вектор разностей всех индексов.
10. **Вектор направлений:** =, <, > для нулевых, положительных и
    отрицательных компонент. Истинная зависимость - если первая не-= компонента
    `<`, её несёт этот цикл. Циклы на позициях `=` параллелятся свободно, на
    `>` - с копией данных, на `<` - нет.
11. **Перестановка циклов** допустима, если все векторы направлений
    остаются лексикографически неотрицательными.
12. **Почему пришлось менять код для 5000 x 5000.** Массив
    `double a[5000][5000]` (200 МБ) на стеке переполняет стек (8 МБ).
    Можно поднять лимит (`ulimit -s`, `-Wl,-stack_size`), но macOS ограничивает
    его 64 МБ, и это не касается стеков других потоков; здесь сетка в куче.
13. **Циклы из методички:**
    - `a[i] = d[i] + 5*i; c[i] = a[2*i] * 2;` - антизависимость: сначала все
      `c[i]` по старому `a` (кроме `c[0] = d[0] * 2`), потом все `a[i]`; оба
      цикла параллельны.
    - `c[i] = sin(a[2*i]); a[i] = d[i]*2;` - то же: два параллельных цикла.
    - `a[i] = a[i-1]*2;` - истинная, D = 1: рекуррентность, последовательно
      (или параллельный префикс).
    - `a[i] = a[i+4]/2;` - антизависимость, D = -4: параллельно с копией `a`.
    - `a[i] = a[i+4]*tan(a[i-1]);` - есть истинная с D = 1: последовательно.
    - `a[i] = a[i-8]*7;` - истинная, D = 8: до 8 исполнителей, по одному на
      остаток `i mod 8`.
