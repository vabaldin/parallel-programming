# Лабораторная работа 2: эффективное распараллеливание циклов

Эталонный цикл и индивидуальные варианты **1б** (MPI), **2б** и **3б**
(OpenMP): анализ зависимостей, последовательная и параллельная версии,
проверка совпадения результатов, время, ускорение и эффективность.
Эталонный цикл распараллелен и на OpenMP, и на MPI.

## Методика

- Машина: Apple M3 Pro, 5 производительных и 6 энергоэффективных ядер;
  Homebrew clang 20.1.8 (`-O3 -march=native`), libomp, Open MPI 5.0.7.
- Размеры $1000 \times 1000$ и $5000 \times 5000$. Массив в 200 МБ не
  помещается на стек, поэтому сетка лежит в куче, а размеры задаются
  параметрами.
- Замеряется только гнездо циклов, без инициализации и вывода в файл.
  Время - минимум по 30 (1000) или 7 (5000) повторам. Для MPI время включает
  сбор результата на ранге 0; время одного счёта дано отдельно.
- Ускорение $S$ и эффективность $E$ считаются по формулам ниже, где
  $T_{\text{посл}}$ - отдельная последовательная программа, $p$ - число
  исполнителей.
- Графики (`plots.ipynb`): погрешность - статистическая по повторным измерениям,
  кривая - сглаживающий сплайн времени в координатах
  $(\log p, \log T)$, из которого получены и кривые $S$ и $E$.
- Корректность: все версии используют одни и те же тела циклов
  (`include/loops.h`), поэтому результаты совпадают побитово. ctest сравнивает
  их в процессе (`-c`) и через файлы `"%f "`, как требует методичка. При
  $5000 \times 5000$ и 11 исполнителях файлы всех версий тоже идентичны.

$$S = \frac{T_{\text{посл}}}{T_p}, \qquad E = \frac{S}{p}$$

## Анализ зависимостей

$D = \Lambda - K$ - вектор расстояний (итерация-приёмник минус
итерация-источник), $d$ - вектор направлений.

| Цикл | Запись | Чтение | $D$ | $d$ | Зависимость |
|---|---|---|---|---|---|
| эталон | `a[i][j]` | `a[i][j]` | $(0, 0)$ | $(=, =)$ | нет |
| 1б | `a[i][j]` | `a[i-2][j+3]` | $(2, -3)$ | $(<, >)$ | истинная, по $i$ |
| 2б | `a[i][j]` | `a[i+1][j-6]` | $(-1, 6)$ | $(>, <)$ | антизависимость, по $i$ |
| 3б, гнездо 1 | `a[i][j]` | `a[i][j]` | $(0, 0)$ | $(=, =)$ | нет |
| 3б, гнездо 2 | `b[i][j]` | `a[i+1][j-3]` | - | - | внутри нет; истинная от гнезда 1 |

## Эталонный цикл

```c
a[i][j] = sin(2 * a[i][j]);
```

Итерации независимы. OpenMP: `parallel for` по $i$ с `schedule(dynamic, 8)`:
при статическом делении всё ждёт медленные ядра, динамическое подняло $S$
при 11 потоках с 5.2 до 6.4. MPI: блоки строк и `MPI_Gatherv` на ранг 0.

## Вариант 1б (MPI)

```c
for (i = 2; i < ISIZE; i++)
  for (j = 0; j < JSIZE - 3; j++)
    a[i][j] = sin(5 * a[i-2][j+3]);
```

Истинная зависимость с $D = (2, -3)$ по внешнему циклу. Цепочка
$(i, j) \leftarrow (i-2, j+3) \leftarrow \dots$ сохраняет величину

$$k = j + 3 \left\lfloor \frac{i}{2} \right\rfloor,$$

поэтому разные $k$ независимы. Диапазон $k$ делится между рангами поровну по
числу элементов; в каждой строке ранг считает свой непрерывный отрезок
(полоса-параллелограмм) без обменов, а в конце отправляет полосу на ранг 0
одним сообщением с типом `MPI_Type_indexed`. Каждый ранг трогает только свою
полосу, поэтому память не растёт с числом процессов.

![1б](results/1b.png)

$5000 \times 5000$, $T_{\text{посл}} = 66.26$ мс:

| $p$ | всего, мс | $S$ | $E$ | счёт, мс | $S$ | $E$ |
|---|---|---|---|---|---|---|
| 1 | 67.47 | 0.98 | 0.98 | 67.46 | 0.98 | 0.98 |
| 2 | 38.51 | 1.72 | 0.86 | 34.83 | 1.90 | 0.95 |
| 4 | 25.81 | 2.57 | 0.64 | 17.94 | 3.69 | 0.92 |
| 6 | 23.94 | 2.77 | 0.46 | 15.41 | 4.30 | 0.72 |
| 8 | 25.03 | 2.65 | 0.33 | 14.94 | 4.43 | 0.55 |
| 11 | 27.14 | 2.44 | 0.22 | 19.31 | 3.43 | 0.31 |

$1000 \times 1000$ ($T_{\text{посл}} = 2.69$ мс): лучшее $S = 2.95$ при 4
процессах.

Счёт масштабируется почти линейно до 4 процессов ($E = 0.92$). Дальше мешают
сбор 200 МБ на ранг 0 (около 10% последовательного времени, по Амдалу
$S \le 10$) и статическое деление на неравных ядрах: в macOS процессы нельзя
привязать к ядрам, и время определяет самый медленный ранг.

## Вариант 2б (OpenMP)

```c
for (i = 0; i < ISIZE - 1; i++)
  for (j = 6; j < JSIZE; j++)
    a[i][j] = sin(0.2 * a[i+1][j-6]);
```

Антизависимость с $D = (-1, 6)$: каждое чтение должно видеть исходное
значение. По методичке такой цикл можно распараллелить, если продублировать
входные данные.

Схема `2b`: строки режутся на $8p$ блоков (`schedule(dynamic, 1)`), внутри
блока строки идут по порядку. Блок читает чужой только первую строку
следующего блока, поэтому до начала счёта эти строки копируются (барьер
после первого `omp for`). Цена - одна строка на блок.

Альтернатива `2b-cols`: $i$ последовательно, `omp for` по $j$ в каждой
строке. Копий нет, но 5000 барьеров на 14 мкс работы каждый, и это медленнее
последовательной версии при любом $p > 1$.

## Вариант 3б (OpenMP)

```c
for (i = 0; i < ISIZE; i++)
  for (j = 0; j < JSIZE; j++)
    a[i][j] = sin(0.01 * a[i][j]);
for (i = 0; i < ISIZE - 1; i++)
  for (j = 3; j < JSIZE; j++)
    b[i][j] = a[i+1][j-3] * 2;
```

Внутри гнёзд зависимостей нет; второе гнездо читает `a`, посчитанное первым.
Слияние гнёзд дало бы $d = (>, <)$, то есть чтение раньше записи, поэтому оно
недопустимо. Схема: одна параллельная область с двумя `omp for`, между ними
неявный барьер. Первый цикл - `schedule(dynamic, 8)`, второй (копирование) -
`schedule(static)`.

| 6 | 16.56 | 4.35 | 0.73 |
| 8 | 15.24 | 4.73 | 0.59 |
| 11 | 13.77 | 5.23 | 0.48 |

$1000 \times 1000$ ($T_{\text{посл}} = 2.80$ мс): $S = 5.11$ при 11 потоках.

## Итоги

| Цикл | Технология | Лучшее $S$ (5000) | $E$ при нём | $E$ при $p = 4$ |
|---|---|---|---|---|
| эталон | OpenMP | 6.37 ($p = 11$) | 0.58 | 0.96 |
| эталон | MPI | 3.38 ($p = 8$) | 0.42 | 0.80 |
| 1б | MPI | 2.77 ($p = 6$) | 0.46 | 0.64 |
| 2б | OpenMP | 6.21 ($p = 11$) | 0.56 | 0.94 |
| 3б | OpenMP | 5.23 ($p = 11$) | 0.48 | 0.88 |

Закон Амдала для доли последовательной работы $\alpha$:

$$S = \frac{1}{\alpha + \frac{1 - \alpha}{p}} \le \frac{1}{\alpha}$$

- До 4 потоков (все на производительных ядрах) OpenMP близок к линейному
  ускорению: из $S = 3.83$ при $p = 4$ доля последовательной части
  $\alpha \approx 0.015$.
- После 5 потоков добавляются медленные ядра: $S = 6.37$ при 11 потоках
  соответствует примерно $5 + 6/3 = 7$ быстрым ядрам, то есть упор в железо,
  а $E$ падает, потому что $p$ считает медленное ядро как полное.
- MPI ограничен сбором результата на ранге 0 ($\alpha \approx 0.1$) и
  статическим делением, поэтому максимум при 4-8 процессах.
- При $1000 \times 1000$ цикл идёт меньше 3 мс, и накладные расходы
  (потоки, барьеры, сообщения) заметнее.
